# Mo Login (Shared Workspace) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mo gets his own login; Sooz work is shared, General contacts and Personal/Career opportunities are per person.

**Architecture:** The owner's user id is the workspace. A `members` table maps each login to its workspace; a `getScope()`
helper returns `{ userId, workspaceId, isOwner }`. Shared rows stay under the workspace id; personal rows under each
user's id. Sooz people in General carry `contacts.shared = true`. Pages pass `workspaceId` for shared sections and
`userId` for personal ones; record pages resolve which id owns an accessible record before calling existing queries.

**Tech Stack:** Next.js 16 App Router, Drizzle 0.45 + Neon, Better Auth, Vitest (integration on the Neon dev branch).

**Spec:** `docs/superpowers/specs/2026-10-27-mo-login-design.md`.

## Global Constraints

- Shared: companies/contacts/deals/activities/tasks in Restaurants and Investors; Sooz-feed radar items and runs;
  outreach, outreach messages, shortlist; app settings. Personal: General contacts/companies (unless `shared`),
  activities/tasks on them, unattached tasks, Personal/Career radar items, LinkedIn connections (`network`).
- Sooz people in General (`contacts.shared`) are visible to both; a member sees a workspace row only if it is shared.
- A user with no `members` row is their own workspace. Public sign-up stays off; only the owner adds/removes members.
- `rr_owner()` = the `members` owner (fallback: the only non-`@example.test` user). New migrations only; routine grants
  unchanged. Outreach drafts stay in Risus's Gmail under his name.
- Branch `mo-login`; commit per task with the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` trailer.

## Review Focus

1. Mo opening `/general/<Risus's friend's id>` (or any action posting that id) gets not-found, never the record.
2. Search, export, Home counts and the sidebar badge never include the other person's personal rows.
3. Routines keep working with two users (`rr_owner`, `rr_ingest` defaults) and write only to the owner's workspace.
4. Approving a Sooz celebrity never attaches to a personal contact of the same name; it is shared.
5. Removing a member deletes only that member's own rows, never shared workspace rows.

Each line has a test in the owning task (Tasks 2, 2, 1, 1, 1).
